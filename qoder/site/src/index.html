知栈 StudyStack 是一个本地优先的课程笔记复习助手：导入 Markdown / TXT 笔记， 在浏览器里算好向量，交给 OceanBase seekdb 用一条 SQL 完成全文 + 向量的混合检索， 再把每次命中的知识点沉淀成掌握度，下次先复习薄弱点。

Why

期末复习时真正卡住的三件事

🔍

知识点找不到

笔记散在十几个 Markdown / TXT 里，只记得“好像在哪篇写过”，关键词又对不上原句。

🫥

薄弱点说不清

刷过的题、看过的段落没有留下痕迹，第二遍复习仍然从第一页开始。

🔒

不敢往云端传

课程笔记、实验数据往往不便上传；通用笔记软件又缺少库内的向量检索能力。

知栈的答案：本地解析 + 本地向量化 + 库内混合检索 + 可追踪的掌握度。

Features

四个 tab 覆盖完整复习闭环

🗂️

多课程知识库

每门课一个 seekdb collection，新建 / 切换 / 删除，实时显示文档数、分块数与向量维度。

📥

导入即向量化

支持 .md / .txt / .json，按句子边界分块（大小、重叠可调），示例笔记一键导入。

⚡

库内混合检索

全文 ngram + HNSW 向量 + RRF 融合全部在 seekdb 单条 SQL 内完成，应用层不重排。

🧠

薄弱点驱动复习

结果可加入复习并标记 会 / 模糊 / 不会，薄弱点 Top 5 按掌握度排序，一键跳回原文。

Engine

一次检索，一条 SQL，三种信号

向量在浏览器里算，检索在数据库里做。服务端只负责把参数装进 @search_parm， 再由 DBMS_HYBRID_SEARCH.GET_SQL 生成并执行真正的混合检索语句。

为什么检索要放在库里

全文召回、向量近邻、融合排序如果拆到应用层，就要把候选集反复搬进内存并自己实现 RRF。 seekdb 的 DBMS_HYBRID_SEARCH 把三件事压进一句 SQL，排序语义由数据库保证，应用层只做映射。

为什么向量要放在浏览器

模型与笔记都不离开本机：模型由本地 /models 静态托管（allowRemoteModels=false）， 服务端只收到向量与文本，天然规避了“笔记上传云端”的顾虑。

Reproduce

三步跑起来

1

准备模型与依赖

terminal
cd qoder/app
npm install
# 模型放到 app/models/Xenova/bge-small-zh-v1.5（约 159MB，q8 实际加载 22.9MB）
huggingface-cli download Xenova/bge-small-zh-v1.5 \
  --local-dir models/Xenova/bge-small-zh-v1.5
2

启动 API 与前端

terminal
npm run dev      # API 8787 + Vite 5173
open http://localhost:5173

顶部出现 WebGPU · q8 · 22.9MB 即模型就绪。

3

按样例走一遍

  1. 课程管理 → 新建 ml_basics → 切换为当前课程
  2. 导入笔记 → 导入示例笔记（机器学习 12 篇）→ 提示 成功导入 12 个示例分块
  3. 检索 过拟合太严重应该怎么缓解 → Top 3 命中 决策树 / 正则化 / 偏差方差
  4. 三条结果加入复习 → 薄弱点页标记 不会 / 不会 / 会 → Top 5 顺序随之变化

命令行等价验证：node scripts/smoke.mjs，预期 All tests PASSED。
